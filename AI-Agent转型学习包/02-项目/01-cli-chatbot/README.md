> 对应模块：**模块 01、02**｜完成周次：**W2**

## 这个项目解决什么问题

把"调用大模型 API"变成一个**你自己能理解、能控制、能度量**的工具。读完模块 01、02 的概念后，这个项目是让你把这些概念真正落地的载体。

**核心目的不是"做一个聊天机器人"**，而是让你在写代码过程中建立三个直觉：

1. **成本直觉**：每次对话花了多少钱，钱花在哪
2. **上下文直觉**：为什么不能无限累积历史，什么时候该裁剪
3. **流式直觉**：为什么必须流式，首字延迟意味着什么

## 快速开始

```bash
# 1. 进入目录
cd "AI-Agent转型学习包/02-项目/01-cli-chatbot"

# 2. 配置密钥
cp .env.example .env
# 编辑 .env，填入你的 DEEPSEEK_API_KEY

# 3. 安装依赖
uv sync

# 4. 运行
export PYTHONPATH=.
uv run main.py
```

### 使用示例

```bash
# 交互式对话（推荐）
uv run main.py

# 单次提问（脚本化）
uv run main.py --once "用三句话解释什么是向量数据库"

# 用更强的模型（对比质量与成本差异）
uv run main.py --model pro

# 用本地 Ollama（零成本调试，需先 brew install ollama && ollama pull qwen3:8b）
uv run main.py --model ollama

# 调高温度（观察随机性差异）
uv run main.py -t 1.2

# 纯文本输出（不用富文本）
uv run main.py --plain
```

### 三个设计要点（值得学习的设计决策）

**1. 为什么配置要集中在 `config.py`？**

模型名、价格、温度这些参数会频繁调整（换模型、官方调价）。集中管理改一处即生效，不会出现"有的地方用 flash 有的地方用 pro"的混乱。

**2. 为什么"已经输出过内容就不能重试"？**

```python
emitted = False
for chunk in stream:
    emitted = True
    yield chunk
# 重试前检查：
if emitted:
    raise RuntimeError("已输出部分内容，无法安全重试")
```

流式场景下，如果已经推了 100 个字给用户，重试会从头生成，用户会看到内容接了两遍。这个细节很多人会忽略。

**3. 为什么裁剪时要保留摘要？**

纯滑动窗口会丢失早期信息——用户在第一轮说"我是 Python 开发者"，第 15 轮时模型已经忘了。摘要压缩把早期内容变成要点保留，兼顾 token 和记忆。

## 常见问题排查

| 症状 | 原因 | 解决 |
|---|---|---|
| `RuntimeError: 缺少环境变量 DEEPSEEK_API_KEY` | 没配 `.env` | `cp .env.example .env` 并填入 Key |
| `ModuleNotFoundError: No module named 'src'` | 没设 PYTHONPATH | `export PYTHONPATH=.` 或从项目根目录运行 |
| 输出不流式（一次性出现） | 终端缓冲 | 确保用了 `uv run`；试试 `--plain` |
| `openai.AuthenticationError` | Key 错误或已失效 | 检查 `.env` 内容，确认 Key 有效 |
| Ollama 模式报连接错误 | 服务没启动 | `ollama serve` |
| 中文显示乱码 | 终端编码 | `export PYTHONIOENCODING=utf-8` |
