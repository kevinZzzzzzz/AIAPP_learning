# 12 周学习路线与验收标准

> 这是整套材料的**总调度表**。每周只做一件事：读模块文档 → 敲代码 → 通过验收。
> 起算日：2026-09-14（周一）

---

## 一、总原则

### 1.1 每周节奏（固定动作）

| 时间 | 做什么 | 时长 |
|---|---|---|
| 周一–周二 | 读模块文档，理解概念，**不做笔记摘抄**，只画一张自己的流程图 | 3–4h |
| 周三–周四 | 把模块里的代码示例全部敲一遍，跑通（不许复制粘贴） | 3–4h |
| 周五 | 复盘：记录踩的坑，回答模块末尾的自测题（答不出来就回去补） | 1–2h |
| 周六–周日 | 做本周的「产出物」，这是唯一需要"做出来"的东西 | 8–12h |

**周五复盘是硬要求。** 不写复盘的一周，等于没学——因为你不知道自己哪里不会。

### 1.2 验收标准（什么叫做"过关"）

每周的产出必须满足三个条件才算过关：

1. **能跑**：代码在干净环境下能启动，不依赖你本机的魔法状态
2. **能讲**：能不看代码，用大白话讲清这周学的核心机制是怎么运作的
3. **能改**：能在 30 分钟内给它加一个小功能（比如加个新参数、换个模型）

只要有一条不满足，宁可花周末补，也不要往前赶。**欠的技术债会在第 7 周集中爆炸。**

### 1.3 进度落后时怎么砍

按这个顺序砍，从下往上砍：

```
❌ 最先砍：模块 06 多 Agent 协作（W9）—— 知道概念即可，不做项目
❌ 其次砍：模块 09 的进阶评估（LLM-as-Judge、A/B 测试）
❌ 再次砍：模块 10 的 K8s / 多租户部分 —— 会用 Docker + Railway 部署就够
✅ 死保：模块 01–05（基础）、07（后端）、08（前端）、至少一个完整项目
```

## 七、W6（10/19–10/25）：Tool Calling 工具调用

**目标**：让模型能调用你写的函数去"做事"，而不只是"说话"。

| 项 | 内容 |
|---|---|
| 读 | `01-文档/模块04-Tool-Calling工具调用/README.md` |
| 敲 | 工具定义与 Schema、单工具调用、多工具选择、并行调用、参数校验、失败重试 |
| 产出 | 一个能查天气 + 联网搜索 + 执行计算的聊天机器人（含工具执行过程可视化） |
| 验收 | ① 能解释模型是怎么"决定"调用哪个工具的（不是模型执行代码，是模型输出一个结构化意图，你的代码去执行）<br>② 能说清一次完整的工具调用往返有几次 API 请求<br>③ 能演示工具报错时你的程序怎么优雅降级 |
| 关键能力 | **Schema 设计**——工具描述写得好不好，直接决定模型调得对不对。这是 Prompt 工程在工具场景的延续 |

**本周最容易踩的坑**：
- 工具描述写得含糊，模型该调时不调、不该调时乱调
- 没有循环上限，模型反复调用同一个工具转不出来（死循环）
- 工具报错直接把异常抛给模型，模型开始"编造"工具结果
- 忘了做权限校验——模型可以决定调用任何你注册的工具，危险操作必须加人工确认

## 十六、写在最后

转型中最容易发生的两件事：

1. **第 3 周放弃**——因为发现要学的东西太多。（应对：只看本周模块，别看全景图，会焦虑）
2. **第 8 周迷失**——框架 API 变来变去，感觉学了就过时。（应对：记住你学的是**模式**不是 API。ReAct 这个模式十年后还在，某个库的方法名三个月后就变了）

**唯一真正决定成败的指标：每周是否有可运行的新代码产出。** 有，你就在前进；没有，学再多概念都是原地踏步。
