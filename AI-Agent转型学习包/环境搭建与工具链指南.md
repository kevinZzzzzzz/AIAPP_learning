## 一、Python 环境（uv 方式，推荐）

### 1.1 为什么用 uv 而不是 pip + venv

| 对比 | pip + venv | uv |
|---|---|---|
| 装依赖速度 | 慢 | **快 10–100 倍** |
| 锁文件 | 需手动用 pip-tools | 原生 `uv.lock` |
| Python 版本管理 | 需 pyenv | 内置 |

你已经装了 uv，直接用。

### 1.2 每个项目的标准起手式

```bash
# 进入项目目录
cd ~/Documents/code/AIAPP_learning/AI-Agent转型学习包/02-项目/01-cli-chatbot

# 初始化（创建 .venv + pyproject.toml）
uv init --python 3.13

# 安装依赖
uv add openai python-dotenv rich

# 运行脚本（注意是 uv run，不是 python）
uv run main.py
```

`uv run` 会自动用项目内的 `.venv`，不会污染系统环境。

### 1.3 常用命令速查

```bash
uv add <包名>            # 添加依赖
uv add --dev <包名>      # 添加开发依赖（只本地用）
uv remove <包名>         # 移除依赖
uv sync                  # 按 lock 文件恢复环境（换机器/新人接手时用）
uv run <命令>            # 在项目环境里执行命令
uv python list           # 查看可用的 Python 版本
```

> **如果某个包 uv 装不上**：少数包对 uv 的解析器不友好，退回 `python -m venv .venv && source .venv/bin/activate && pip install <包名>` 也能用。不要在这上面耗超过 15 分钟。

## 二、API Key 配置（第 1 天必须做）

### 2.1 为什么必须用 .env

把 Key 写死在代码里，一旦推到 GitHub，**爬虫会在几分钟内扫到并盗刷**。这是新手最常见的"学费"。刷爆几千块的案例每年都有。

### 2.2 标准做法

**第 1 步**：项目根目录建 `.env`

```bash
# .env —— 这个文件绝对不能提交到 Git
DEEPSEEK_API_KEY=sk-你的key
DASHSCOPE_API_KEY=sk-你的key

# 可选：如果用 OpenAI / Claude
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
```

**第 2 步**：项目根目录建 `.gitignore`

```gitignore
.env
.env.local
.venv/
__pycache__/
node_modules/
*.pyc
.DS_Store
data/
chroma_db/
*.db
```

**第 3 步**：建 `.env.example`（**这个要提交**，给别人看需要哪些变量）

```bash
DEEPSEEK_API_KEY=your_key_here
```

**第 4 步**：代码里读取

```python
import os
from dotenv import load_dotenv

load_dotenv()  # 从 .env 加载到环境变量

api_key = os.getenv("DEEPSEEK_API_KEY")
if not api_key:
    raise RuntimeError("缺少 DEEPSEEK_API_KEY，请检查 .env 文件")
```

> **立刻做一次自检**：`git status` 看一下，确认 `.env` 不在待提交列表里。以后每新建项目都做一次。

### 2.3 推荐注册的 API（按性价比排序）

| 提供方 | 用途 | 成本 | 备注 |
|---|---|---|---|
| **DeepSeek** | 主力模型（生成、推理、工具调用） | 极低 | `deepseek-v4-flash` 输出 $0.28/百万 token，学练足够 |
| **阿里云百炼** | Embedding + Rerank | 极低 | `text-embedding-v4` ¥0.5/百万 token，新用户 90 天 100 万 token 免费 |
| OpenAI | 补充，文档最全 | 较高 | 需要用 Responses API 时再充 |
| Anthropic | 补充，长上下文强 | 较高 | 按需 |

**学习阶段总成本预估**：做完 4 个项目，**¥50 以内足够**（前提是用 DeepSeek + 百炼，且不开不必要的推理模式）。

### 2.4 省钱三条铁律

1. **开发调试用便宜模型或本地模型**，只在最终验证时用贵模型
2. **善用 prompt caching**：DeepSeek 缓存命中的输入价格是未命中的 1/50（$0.0028 vs $0.14），把固定不变的长 Prompt 放在前面能大幅省钱
3. **随手统计 token**：写一个累计消耗的小工具，每跑一次实验心里有数

## 三、本地模型（可选，强烈建议）

本地模型的三个好处：**零成本调试**、**离线可用**、**敏感数据不出本机**。

### 3.1 安装 Ollama

```bash
brew install ollama
ollama serve          # 启动服务（或 brew services start ollama）
```

### 3.2 拉取模型（按机器配置选）

```bash
# 通用对话，7B 级别，16G 内存机器可跑
ollama pull qwen3:8b

# 更轻量，8G 内存可跑
ollama pull qwen3:4b

# 代码相关
ollama pull qwen2.5-coder:7b
```

### 3.3 接入代码（Ollama 兼容 OpenAI 协议）

```python
from openai import OpenAI

# 关键：base_url 指向本地
client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

resp = client.chat.completions.create(
    model="qwen3:8b",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)
```

> **注意**：本地小模型的工具调用（Tool Calling）能力通常较弱，容易调错或格式不对。**调试链路逻辑用本地模型，验证工具调用质量用云端模型。**

## 九、常见环境问题速查

| 症状 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError` | 装到了别的环境 | 用 `uv run` 而不是裸 `python` |
| `401 Unauthorized` | Key 错/没加载 | 确认 `.env` 路径正确、`load_dotenv()` 已调用、变量名拼写一致 |
| `429 Too Many Requests` | 触发限流 | 加重试 + 指数退避；或换轻量模型 |
| `context_length_exceeded` | 上下文超限 | 需做截断或摘要（见模块 05 记忆部分）|
| 中文乱码 | 编码问题 | Python 文件头 `# -*- coding: utf-8 -*-`，或确认读写用 `encoding='utf-8'` |
| pip 装包编译失败 | 缺系统依赖 | macOS：`xcode-select --install` |
| 流式输出卡住不结束 | 未处理结束标记 | 检查是否正确遍历完流，或加了超时 |
| `uv` 解析冲突 | 依赖版本矛盾 | 用 `uv add "包名>=x.y"` 放宽约束，或退回 venv+pip |


- 每个项目都要有 README，写清"这是什么、怎么跑、学到什么"——三个月后你会感谢自己
