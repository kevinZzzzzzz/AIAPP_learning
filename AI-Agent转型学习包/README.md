## 一、先看结论：这套材料怎么用

**三条使用规则，照做就行：**

1. **按周推进，不跳步。** 每周只做一件事：读对应模块文档 → 亲手跑通代码 → 完成本周验收。总调度表在 `12周学习路线与验收标准.md`。
2. **文档是地图，项目才是路。** 模块文档讲清"概念 + 为什么"，`02-项目/` 里的代码让你真的跑起来。看懂 ≠ 会写，每个示例都要自己敲一遍。
3. **每周产出必须能当场演示。** 12 周后你手里会有 4 个能跑的项目 + 1 份作品集说明。面试讲项目，不背概念。

**推荐阅读顺序**（也是文件组织顺序）：

```
README.md（本文）
   ↓ 先看这个，知道全貌
12周学习路线与验收标准.md

   ↓ 第 1 天就把环境装好，别边学边配
```

## 二、你的起点和终点

### 2.1 起点：你已经有的，别浪费

| 前端已有能力 | 在 Agent 开发里怎么用 |
|---|---|
| 异步 / Promise / 状态管理 | Agent 的多步执行、状态机、并发工具调用，本质是同一类问题 |
| 组件化拆分思维 | Agent 系统拆解：规划器、工具层、检索层、记忆层 |
| 接口联调 / 排错能力 | Agent 的排错链路更长（模型 + 提示词 + 工具 + 检索），排错能力是硬通货 |
| 流式渲染、SSE 使用经验 | AI 对话产品的核心体验就是流式，这是你的主场 |
| 工程化（类型、构建、测试） | 90% 的 AI 开发者工程能力弱，这是你的差异化优势 |

### 2.2 终点：12 周后你应该能做什么

能用一句话说清"我这个 Agent 系统怎么设计、怎么保证质量、怎么控制成本"，并且有代码可以证明：

- 独立用 FastAPI 搭一个带流式输出的 Agent 后端服务
- 独立搭一个能查文档、给引用、可评估的 RAG 系统
- 独立设计工具（Tool）并处理多步调用、失败重试、权限校验
- 用 LangGraph 编排有状态、可中断、可恢复的 Agent 流程
- 用 Next.js 做流式对话 UI，并把工具执行轨迹、引用来源展示清楚
- 给 Agent 建评测集、算成本、看链路，能说清"做得好不好"

### 2.3 明确**不要**学的（省下至少 100 小时）

| ❌ 不要碰 | 原因 |
|---|---|
| 模型训练 / 微调底层 | 需要 CUDA、分布式训练、海量算力，是算法岗的事。**但不排斥了解微调的概念边界** |
| Transformer 论文逐行推导 | 你只需要知道模型"能干什么、边界在哪、为什么会有幻觉"，不需要会推导注意力公式 |
| 同时深挖 3 个框架 | LangChain / LlamaIndex / CrewAI 全学会导致样样稀松。本包**深挖 LangGraph**，其余知道用途即可 |
| 追求前端 UI 完美 | 这是前端转行最大的陷阱。UI 用现成组件库，时间全留给 AI 逻辑 |
| Prompt 玄学式调参 | 别"感觉一下改改词"。要建立可复现的评测，用数据说话 |

## 六、前端转 Agent 的 5 条铁律

1. **代码量 > 课程量。** 看完一个概念立刻写代码。连刷 3 小时视频 = 0 收获。
2. **前端是你的秘密武器，不是包袱。** 大多数 AI 开发者的 UI 一塌糊涂，你能做出"体验好 + 看得懂 AI 在干什么"的产品，这在面试里极其加分。
3. **先跑通最小闭环。** 不要一上来就设计"全功能 Agent 平台"。一个 Agent + 两个工具跑通，比 10 个半成品强。
4. **不要追新。** 框架三个月一换代。学的是**模式**（ReAct、RAG、人在环），不是某个 API 的写法。API 会变，模式不会。
5. **建立数据敏感度。** "什么样的数据适合 RAG""怎么判断检索质量"这类问题比写代码难，也更有价值。这是高级岗和初级岗的分水岭。
